## โครงสร้าง

แต่ละแอพเป็นไฟล์ HTML ไฟล์เดียว รวม CSS + JS ไว้ในตัว ไม่มีขั้นตอน build
อัปไฟล์ขึ้นโฮสต์ได้เลย

ข้อมูลเก็บใน Supabase เป็น key → JSON ผ่านตาราง `kv_store`

แต่ละแอพอ่านคีย์ของอีกฝั่งด้วย เพื่อคำนวณสต๊อกข้ามแอพ — เบิกที่ฝั่งผลิต ยอดในฝั่งสต๊อกลดทันที

## สิ่งที่หักสต๊อกอัตโนมัติ

- **ถุงซิล + ถุงแพ็ค** — หักทุกครั้งที่บันทึก 1 แพ็ค ตามเบอร์กระสอบที่แท็กไว้ กระสอบหมดไหลไปเบอร์ถัดไปเอง
- **ใย** — หักทุกครั้งที่แตะ +1 รอบป้อนใย ตามสูตร ไล่จากล็อตเก่าสุด ผูกกับเบอร์ก้อนที่แท็กไว้
- ลบรายการที่บันทึกผิด = คืนของเข้าสต๊อกให้อัตโนมัติ

## กติกาการเขียนข้อมูล

- **ตัวคูณใช้ `x` เสมอ** (`18x28` ไม่ใช่ `18*28`) พิมพ์ `*` `×` `X` มา ระบบแปลงให้เอง
- ชื่อผ้า/ไซซ์ที่พิมพ์ไม่ตรงกันจะถูกเตือนอัตโนมัติ และแก้รวมเป็นชุดเดียวได้ที่แท็บผ้า

## ความปลอดภัย — ยังไม่ได้เปิดใช้

ตอนนี้แอพที่ใช้งานอยู่ **ไม่มีหน้าล็อกอิน** ใครที่รู้ URL แล้วกดดูซอร์สโค้ด
จะอ่านและแก้ข้อมูลสต๊อก/ออเดอร์ได้ทั้งหมด — รับความเสี่ยงนี้ไว้ก่อนโดยตั้งใจ

เวอร์ชันที่ปิดช่องโหว่แล้วเตรียมไว้ให้ พร้อมใช้เมื่อไหร่ก็ได้

| ไฟล์ | คือ |
|---|---|
| `stock-app_1-ล็อกอิน.html` | แอพสต๊อก + หน้าล็อกอิน (เนื้อในเท่ารอบ 23 ทุกอย่าง) |
| `factory-app-supabase-ล็อกอิน.html` | แอพผลิต + หน้าล็อกอิน |

ผ่านเทสระบบล็อกอิน 20/20 (`test_auth.js`) แล้ว

### ⚠ ยังอัปทับตัวหลักไม่ได้ — ตรวจแล้วเมื่อ 24 ส.ค. 2569

**ยังไม่มีบัญชีผู้ใช้ใน Supabase สักอัน** (Authentication → Users ว่างเปล่า)
ถ้าอัปไฟล์ที่มีล็อกอินขึ้นตอนนี้ ทุกเครื่องจะเจอหน้าให้กรอกรหัสที่ไม่มีรหัสให้กรอก = ใช้งานไม่ได้ทั้งโรงงาน

และช่องโหว่จริงอยู่ที่ตาราง `kv_store` มี policy `allow anon read/insert/update` เปิดให้ role `public`
[`rls.sql`](rls.sql) ตัวล่าสุดแก้ให้ลบ 3 อันนี้ทิ้งก่อนแล้ว (ของเดิมแค่เพิ่ม policy ใหม่ ปิดช่องโหว่ไม่ได้จริง)

ทำตามลำดับใน [SECURITY-SETUP.md](SECURITY-SETUP.md) — สร้างบัญชี → อัปไฟล์ → ล็อกอินให้ครบทุกเครื่อง → รัน `rls.sql`
